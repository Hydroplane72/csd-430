# Use CSRF (Cross-Site Request Forgery) tokens

## What is it?:
CSRF (Cross-Site Request Forgery) tokens are unique, secret values generated by the server and included in HTTP requests to protect against CSRF attacks. These tokens help ensure that the request is from an authenticated user and not a malicious source. The client must include the token in the request, and the server will validate it before processing the request. If the token is missing or invalid, the server will reject the request, thus preventing unauthorized actions.

## How do we implement it?:

To implement CSRF tokens, you can follow these steps:
1. Generate a unique CSRF token for each user session on the server side.
2. Include the CSRF token in the header of requests.
3. Validate the CSRF token on the server side before processing the request.

Here is an example of a Token service class in Java:

``` Java

import javax.servlet.http.HttpServletRequest;
import javax.servlet.http.HttpServletResponse;
import javax.servlet.http.HttpSession;
import java.util.UUID;
public class CsrfTokenManager {

    public static final String CSRF_TOKEN_SESSION_ATTR = "csrfToken";

    public static String generateToken() {
        return UUID.randomUUID().toString();
    }

    public static void setToken(HttpSession session) {
        session.setAttribute(CSRF_TOKEN_SESSION_ATTR, generateToken());
    }

    public static String getToken(HttpSession session) {
        return (String) session.getAttribute(CSRF_TOKEN_SESSION_ATTR);
    }

    public static boolean validateToken(HttpServletRequest request) {
        String token = request.getHeader("X-CSRF-Token");
        HttpSession session = request.getSession(false);
        if (session == null) {
            return false;
        }
        String sessionToken = getToken(session);
        return sessionToken != null && sessionToken.equals(token);
    }
}

```


In this example, the `CsrfTokenManager` class provides methods to generate a CSRF token, set it in the user's session, retrieve it from the session, and validate it against the token sent in the request header.


## Why do we care?:

CSRF attacks can lead to unauthorized actions being performed on behalf of an authenticated user, resulting in data breaches, financial loss, and damage to the user's trust. By implementing CSRF tokens, we can significantly reduce the risk of such attacks and protect both users and the application's integrity. This is a security measure that realistically should never be skipped in any web application that handles sensitive data or user interactions.
